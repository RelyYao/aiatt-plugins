# 房间插件开发者指南

给想在上桌里做一个新游戏（或一个房间活动）的人。接口本身见 `docs/design/platform/房间插件接口-room-plugin-v1.md`，整体设计见 `docs/design/platform/房间插件化底层设计-2026-11-24.md` 第十节。本文只讲怎么动手：工具、流程、容易踩的坑。

工具是 `@aiatt/plugin-sdk`（命令 `aiatt-plugin`）。**全部离线可用，不需要账号、数据库和平台代码**：SDK 带着真正的宿主（和线上用的同一份校验、沙箱、动作日志），只是把存储换成内存。需要 Node 22 以上。

## 五分钟上手

```bash
npx aiatt-plugin new my-game        # 生成骨架（井字棋风格，已经能玩、能通过检查）
cd my-game
npx aiatt-plugin dev                # 浏览器里打开 http://127.0.0.1:5173/，自己坐一个座位，其余是 Bot
npx aiatt-plugin test               # 一致性 + 泄露 + 模糊测试 + 禁用 API 扫描 + 包大小
```

改 `server/index.js` 保存，模拟器自动重载，并把这一局已经走过的步骤在新代码上重放一遍。

## 命令清单

| 命令 | 做什么 |
|---|---|
| `new <id> [--template match\|activity] [--dir 目录] [--author 名字]` | 生成插件骨架。`match` 是对局（开局、回合、结果），`activity` 是房间存在期间一直运行的活动。`id` 是 2–40 位小写字母、数字、连字符 |
| `check [目录]` | 清单校验、打包、沙箱加载、必需的函数（`decisions` `apply` `view` `result`，对局还要 `setup`）；还会提醒缺 `timeout()`、缺 `secrets()`、缺文案等 |
| `test [目录] [--games 30] [--seed 1] [--fuzz 2000] [--max-steps N] [--json]` | 依次：check、禁用 API 扫描、包大小与依赖、一致性模拟（出错、卡住、泄露、重放不一致）、模糊测试（几千局随机对局必须都能结束，被拒绝的步骤不能改变对局）、Agent 提示模板检查（有 `agent/` 目录时，同 `preview-prompts`）。有任何问题退出码非 0；`--json` 给 CI 用 |
| `build [目录] [--out 文件]` | 沙箱实际运行的单文件 `dist/server.js`，同目录写 `report.json`（大小、gzip、sha256、文件清单）。同样的源文件得到同样的结果 |
| `dev [目录] [--port 5173] [--no-watch]` | 本地模拟器（见下） |
| `preview-prompts [目录] [--limit 12] [--locale zh-CN] [--json]` | 模拟一局，打印 Agent 在每个决策点会收到的提问和期望的回答格式 |
| `replay <日志.json> [--dir 插件目录] [--break-at N] [--inspect]` | 重放导出的动作日志，逐步打印状态哈希，最后和日志里记的最终状态比对 |
| `submit [目录] [--repo 地址]` | 先跑完整 `test`，再构建，写 `dist/submission/`（`server.js`、`report.json`、`plugin.json`、`SUBMISSION.md`），并打印向社区仓库提交合并请求的命令。**不会推送任何东西** |
| `live [目录]` | 调试房（在线上和真人、真 Agent 一起测，代码仍在你电脑上跑）：下一阶段（P4b）提供 |

目录省略时用当前目录。`test` 的 2000 局模糊测试对一个小游戏大约要半分钟（每次调用都是一次带时限的沙箱调用），改代码时可以先用 `--fuzz 200`。

## 一个插件长什么样

```
my-game/
  plugin.json          清单：座位、能力、动作（JSON Schema）、开房选项、限制
  server/index.js      规则：纯函数，在沙箱里运行；可以拆成多个文件（字面相对路径 require）
  locales/zh-CN.json   ctx.t 用的文案（zh-CN / zh-TW / en）
  agent/               可选：prompts.js，Agent 的提问模板和回答格式
  README.md
```

规则写成 `module.exports = definePlugin({ setup, decisions, apply, view, result, … })`，要点：

- **状态和动作都是 JSON**，插件拿到的永远是副本。`apply` 返回 `{ state, events }`，或者 `{ error, message }`（这一步不合法，状态不变；输入本身有问题加 `status: 400`，不是这个座位能做的加 `status: 403`）。
- **随机数用 `ctx.rng()`，时间用 `ctx.now`。** 没有 `Date`、`Math.random`、计时器、`process`、`require`（插件自己的文件和 `@aiatt/plugin-kit/*` 除外）、`eval`、网络、文件。同一个种子和同一串动作必须得到同一个状态：这是复盘、作弊排查和时间旅行的基础。
- **不要在模块里存可变状态**（`let calls = 0` 之类）：重放会不一致，`test` 会指出。
- **隐藏信息**：只在对应座位的 `view(state, viewer)` 里给出；`viewer` 为 `null` 是观战。再写一个 `secrets(state)` 列出「值 + 谁能看」，泄露检查会在每一步、对每个座位和观战视图里找这些值。
- **决策点**：`decisions(state)` 说现在谁能做什么，第一个动作是主要动作。需要计时就声明 `deadlines` 能力并写 `timeout()`（时间到了替这个座位走的一步），这样 Agent 超时、玩家不动都不会卡住对局。
- **Bot 座位**：写 `engine(state, decision, ctx)`，平台自己走的座位（内置 Bot、陪练方）就用它；没有 `engine()` 时模拟器用随机合法动作。

骨架（`new` 生成的井字棋）把这些都用了一遍，直接改最快。更完整的样板在 `plugins/gomoku`（带引擎）和 `plugins/spy`（隐藏信息、多阶段、房主动作）。

## 本地模拟器（`dev`）

在 `127.0.0.1` 上起一个只有 Node 的小服务器，没有依赖，不联网：

- 选座位数和自己坐哪个座位，其余座位是 Bot（有 `engine()` 用它，否则随机合法动作）。可以填种子和开房选项（JSON），同一个种子永远是同一局。
- 「view as」下拉可以切到任何座位或观战，直接看每个人的 `view`（JSON），也就是在检查有没有泄露。`view` 里有 `board`（一维 9、16 等个格子或二维数组）会画成棋盘，有 `hand`（数组）会画成手牌；点棋盘上的格子会把坐标填进动作表单（字段叫 `cell`、`x`/`y`、`row`/`col`），表单里字段全被填满就直接提交。
- 动作表单由清单里的 Schema 生成；「any action as any seat」可以以任何座位发任何 JSON，用来试那些应该被拒绝的输入（拒绝的原因会显示出来）。
- 「Advance clock to next deadline」让宿主执行 `timeout()`。
- **时间旅行**：右边每一步都记着动作、事件、时间和这一步的随机数种子；点「rewind」回到那一步（从种子开始，把记录的动作重放到那里）。回到中间某一步时 Bot 不会立刻再走，点「Let Bots move」让它们走。
- **改代码自动重载**：保存后插件重新加载，整局的动作日志在新代码上重放；新代码让某一步不再合法时，保留到那一步之前并提示丢了几步；新代码加载失败时旧代码继续跑，页面上显示错误。
- 「Download action log」导出这一局的日志，交给 `replay`。

页面上的所有文字（插件名、视图、错误）都按纯文本显示。

## 断点调试

服务端逻辑就在你自己的 Node 里跑：

```bash
npx aiatt-plugin replay match-log.json --inspect --break-at 7
# 等价于：node --inspect-brk <SDK 的 bin/aiatt-plugin.mjs> replay match-log.json --break-at 7
```

`--break-at N` 在应用第 N 步之前停下（一条 `debugger` 语句），往里单步就进到你的 `apply`。调用路径是普通函数调用，没有进程间通信。

## `test` 检查什么，怎么修

| 阶段 | 失败说明 | 常见原因 |
|---|---|---|
| check | 清单、打包或加载有问题 | `plugin.json` 字段不对；`require` 了插件目录以外的东西；缺必需函数 |
| scan | 用了沙箱里不存在的东西（带文件名和行号） | `Date`、`Math.random`、`process`、`setTimeout`、`async`、`eval`、`fetch`；ES 模块的 `import`/`export`（要写 CommonJS） |
| size | 服务端包超过 512 KB 或目录超过 8 MB；`package.json` 有 `dependencies` | 插件不能带第三方依赖（`devDependencies` 可以，例如 SDK 本身） |
| simulate | 随机对局里出错（异常、超时、返回格式不对、状态超限）、卡住（没有决策点又没结束）、泄露、重放不一致 | 状态里存了不能序列化的东西；`view` 把别人的手牌放进去了；模块级可变变量 |
| fuzz | 同上，加上：每一局都必须能结束；被拒绝的步骤不能改变对局；乱七八糟的输入不能让插件抛异常 | 某个分支永远不结束；`apply` 在返回错误前就改了状态 |
| agent | 提示模板和清单对不上 | 模板里的动作名清单里没有；`answer` 生成的回答过不了动作的 Schema；`instruction` 抛异常 |

`--seed N` 换一批随机对局；失败信息里有对局的种子，可以用同样的种子复现。

## Agent 提示

Agent 怎么接入不需要插件额外写代码：平台用 `decisions()` 找出谁该答，用动作的 Schema 校验回答，用 `timeout()` 兜底。想让提问更好，写 `<插件>/agent/prompts.js`：

```js
module.exports = {
  place: {
    instruction: (view, decision, t) => t('agent.place', { board: view.board.join('') }),
    answer: { type: 'object', properties: { cell: { type: 'integer', minimum: 0, maximum: 8 }, reason: { type: 'string', maxLength: 80 } }, required: ['cell', 'reason'] },
  },
};
```

没有写的动作，平台按动作 Schema 和视图生成默认提问。`preview-prompts` 把两种都打印出来，并检查：模板里的动作名在清单里、`answer` 是合法的 Schema、按 `answer` 生成的回答能通过动作的 Schema。回答里要带一句 `reason`，平台会把它记进对局记录，赛后 Agent 能想起自己当时为什么这么走。

## 提交上线

1. `npx aiatt-plugin submit`：完整跑 `test` 并构建，通过后写出 `dist/submission/`，终端打印命令。
2. 在 GitHub 上 fork 社区仓库，把命令里的 `<community-repo-url>` 换成你 fork 的地址（或用 `--repo` 直接给），逐条执行：新建分支、把插件文件复制到 `plugins/<id>/`、提交、推送、`gh pr create`（合并请求正文就是 `SUBMISSION.md`）。
3. 社区仓库的自动检查会把同样的检查再跑一遍；人工审核看玩法、文案、能力申请和提示模板。
4. 合并后同步进平台，随下一次发布上线；作者收益（作者 70%、平台 30%，第一期以 T 分发放）的规则见设计文档 10.3。

`SUBMISSION.md` 里有作者自查清单（文案、隐藏信息、能力申请、素材许可证、不含密钥）。

## 在平台仓库里用 SDK / 导出仓库

SDK 在平台仓库里是 `packages/plugin-sdk`，宿主文件取自 `lib/plugins/`；导出到开源仓库后，宿主文件在 `sdk/host/`，SDK 自动改用那里。规则只有一条（`packages/plugin-sdk/src/load-host.js`）：`../host/plugin-host.js` 存在就用它，否则用 `../../../lib/plugins/`。两种位置下宿主的存储请求都由 `packages/plugin-sdk/src/store-shim.js`（内存实现）回答，不会加载平台的真实存储，也不会写磁盘。

在平台仓库里想直接用 SDK 的命令：`node packages/plugin-sdk/bin/aiatt-plugin.mjs test plugins/gomoku`。原来的 `scripts/plugin-dev.mjs`（check、simulate、build）继续可用。

## 现在的边界

- 模拟器和 `test` 用的沙箱是 Node 的 `vm`：它拦住平台对象、模块和进程，但不是对抗恶意代码的安全边界。审核通过前的社区代码只在作者自己的电脑上跑；社区插件上线后换独立进程运行（设计文档 P5）。
- 前端（`client/`）的开发和构建不在这一版 SDK 里。
- `live` 调试房、`replay` 直接拉线上对局，随 P4b 提供。
